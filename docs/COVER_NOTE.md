# Cover note — AI Engineer Assignment

I built the reconciliation system around Chew's (ICAIF '20) idea that a bank statement and a check register are two "languages" describing the same transactions. Unique-amount matching seeds a parallel corpus of validated pairs. From that corpus I implemented the paper's cross-language SVD model: mutual-information term alignment, a log-entropy term-by-transaction matrix, SVD and cosine retrieval. It learns mappings such as `KROGER`→"grocery", `CK`→"check" and DEBIT→DR without any hand-written rules. Because a text cosine alone only identifies the *kind* of transaction, I embedded it in a hybrid likelihood-ratio scorer (Fellegi–Sunter style). There the text, date-lag, amount-difference and shared-token distributions are all learned from accepted matches. A global 1:1 assignment produces a posterior confidence, so genuinely ambiguous duplicates go to a human instead of being guessed. The CLI runs the paper's monthly loop (match → QC → ML → QC → manual) and persists validated pairs, so each run starts from a better model.

On the provided data the pipeline reaches P = R = F1 = 1.0: 286 unique-amount matches plus 22 ML matches covering the rounding and duplicate-amount cases. Because that dataset is 93% solvable from amounts alone, I evaluated the ML in two harder settings. (1) With amounts hidden, F1 rises from 0.34 with 20 training pairs to 0.91 with 240, at 0.99+ precision. (2) I built a 12-month synthetic extension with 44% non-unique amounts, noise, one-sided entries and a mid-year bank format change. Carrying learning across months lifts ML-stage recall from 0.60 to 0.70 at about 97% precision, and overall automatic F1 is 0.94. The ablations had one honest surprise: the MI alignment step adds nothing measurable over plain cross-language LSI on this data, because concatenated training pairs already give the SVD the co-occurrence signal. Details, ablations and limitations are in `docs/ANALYSIS.md`.

Questions I'd like to discuss:
- In production, should uniqueness be tested within a statement period or across all history, as in the paper? The trade-off is unique-stage recall against coincidental matches.
- Are many-to-one matches (split or batched payments) in scope for the real data?
- For fungible duplicates (two identical ATM withdrawals on the same day), is "either assignment" acceptable, or must the match be exact?
